# Enter-AX 연결형 AX 네트워크 데모 설계

- 작성일: 2026-09-16
- 대상 저장소: `Dazzlar199/dazzlingstudio`
- 배포 대상: 기존 Dazzling Studio Vercel 프로젝트의 Preview 및 Production
- 문서 상태: 구현 전 승인 설계

## 1. 제품 정의

Enter-AX는 지원자가 오디션 프로필과 미디어를 등록하고, 검증된 엔터테인먼트 회사가 이를 검수해 오디션 제안을 보낼 수 있는 연결 플랫폼이다. 연결된 지원자는 엔터사 내부 후보자 파이프라인으로 이동하며, 엔터사는 같은 제품에서 반복 업무와 홍보 콘텐츠 제작을 AI 에이전트로 자동화한다.

첫 공개 버전은 실제 개인정보·미디어를 서버에 저장하지 않는 인터랙티브 데모다. 화면과 데이터 접근 계층을 분리하여 이후 인증, 데이터베이스, 파일 저장소, Hermes Agent, 미디어 분석 및 SNS API로 교체할 수 있게 한다.

### 핵심 가치 흐름

```text
지원자 프로필·오디션 자료 등록
→ 공개 범위와 동의 설정
→ 검증된 엔터사의 검색·검수
→ 관심 저장 또는 오디션 제안
→ 지원자의 수락·거절
→ 엔터사 내부 후보자 파이프라인
→ AX 에이전트 업무 생성·승인
→ 홍보 콘텐츠 자동화·배포 준비
```

### 포지셔닝

> Enter-AX는 단순한 오디션 공고 사이트가 아니라, 인재 발견부터 컨택·사내 검토·콘텐츠 홍보까지 연결하는 엔터테인먼트 AX 운영 플랫폼이다.

## 2. 첫 버전의 목표와 비목표

### 목표

- 지원자와 엔터사의 전체 연결 흐름을 클릭 가능한 데모로 제공한다.
- 지원자 등록에서 정면·좌·우 사진과 보컬·댄스 자료 입력을 체험할 수 있게 한다.
- 엔터사가 인재를 검색하고, 상세 프로필을 검수하고, 제안을 보내는 흐름을 제공한다.
- 수락된 후보자를 팀이 관리하는 칸반 파이프라인을 제공한다.
- 회사 내부 AX Command Center와 에이전트 작업 승인 흐름을 제공한다.
- 홍보영상 자동화의 입력, 처리 단계, 결과 검수, 예약 배포 흐름을 제공한다.
- 모든 가상 자동화 결과에 `데모` 또는 `API 연동 예정` 상태를 표시한다.
- 기존 Vercel 프로젝트에 Preview를 배포하고 검수 후 Production으로 승격할 수 있게 한다.

### 비목표

- 실제 회원가입, 본인인증 또는 엔터사 사업자 인증
- 실제 개인정보·사진·영상의 서버 저장
- 실제 미성년자 법정대리인 인증
- 실제 AI 영상·음성 분석 또는 지원자 자동 순위 산정
- 얼굴 대칭도, 외모, 체형, 스타성 점수화
- 자동 합격·탈락 결정
- 실시간 1:1 채팅
- 실제 이메일·메신저 발송
- 실제 영상 렌더링과 SNS 게시
- 실제 결제와 구독
- Hermes Agent 서버의 운영 배포

## 3. 사용자와 권한

### 지원자

- 프로필과 오디션 자료를 등록한다.
- 기본 공개 범위를 검증된 엔터사 전용으로 설정한다.
- 별도 동의로 공개 포트폴리오를 허용할 수 있다.
- 엔터사의 관심·오디션 제안을 확인하고 수락·거절·추가 정보 요청을 선택한다.
- 프로필을 열람한 엔터사 이력을 확인한다.
- 공개와 컨택 동의를 철회하는 경험을 확인한다.

### 엔터사 직원

- 데모에서는 `검증 완료` 상태로 입장한다.
- 조건별로 인재를 검색하고 상세 프로필과 자료를 검수한다.
- 관심 인재를 저장하고 내부 검토로 이동한다.
- 오디션 제안을 작성하고 발송한다.
- 수락된 지원자를 후보자 파이프라인에서 관리한다.
- AX 업무, 에이전트 실행, 승인 대기 및 콘텐츠 작업을 확인한다.

### 플랫폼 관리자

첫 버전에서는 별도 관리 화면을 구현하지 않는다. 엔터사 검증, 신고 처리, 동의 상태 확인, 접근 감사는 화면의 상태와 설명으로만 모델링한다.

| `/agency` | 엔터사용 가치 설명과 데모 시작 |
| `/agency/discover` | 인재 검색·필터·관심 저장 |

## 5. 지원자 오디션 등록

### 기본 프로필

- 이름 또는 활동명
- 생년월일
- 국적
- 거주 지역
- 지원 분야: 아이돌, 보컬, 댄스, 배우, 모델
- 자기소개
- 선택 SNS 링크
- 미성년자 여부와 보호자 동의 상태

### 얼굴 사진

다음 세 입력을 독립적으로 제공한다.

- 정면
- 왼쪽 측면
- 오른쪽 측면

각 입력에는 촬영 가이드를 제공한다. 파일을 선택하면 `URL.createObjectURL` 기반 로컬 미리보기를 제공하고, 페이지 이탈 또는 새로고침 시 폐기한다. 사진은 인간 심사 참고 자료이며 AI 평가 대상이 아님을 표시한다.

### 보컬·댄스 자료

보컬과 댄스 각각 `직접 파일` 또는 `YouTube 링크` 중 하나를 선택한다.

| 방식 | 데모 동작 | 향후 동작 |
|---|---|---|
| 직접 파일 | 브라우저 로컬 재생·파일 정보 표시 | 저장소 업로드 후 분석 작업 생성 가능 |
| YouTube 링크 | 주소 검증·공식 임베드 재생 | 재생 전용, AI 분석하지 않음 |

YouTube 콘텐츠를 다운로드·캐시·분리 분석하지 않는다. 분석을 원하는 지원자에게 원본 파일 업로드가 필요하다는 설명을 제공한다.

### 동의와 공개 범위

- 기본값은 `검증된 엔터사에만 공개`다.
- `전체 공개 포트폴리오 허용`은 별도 선택이다.
- `엔터사 오디션 제안 수신`을 별도로 동의한다.
- `홍보·마케팅 이용`은 기본 미동의이며 별도 선택이다.
- 미성년자는 보호자 동의 미완료 상태에서 등록을 완료할 수 없다.
- 데모임을 알리는 고정 안내와 파일이 서버에 저장되지 않는다는 설명을 제공한다.

## 6. 엔터사 인재 탐색과 검수

### 검색 조건

- 지원 분야
- 성별과 연령대
- 국적과 거주 지역
- 보컬·댄스 자료 보유 여부
- 직접 파일 보유 여부
- 신규 등록과 최근 활동
- 공개 범위

검색 결과 카드는 얼굴만 과도하게 강조하지 않고 지원 분야, 지역, 연령대, 미디어 보유 상태와 공개 범위를 함께 표시한다.

### 프로필 검수

상세 화면에는 프로필 요약, 정면·좌·우 사진, 보컬, 댄스, 자기소개, 미디어 소스, 팀 메모와 평가를 제공한다. 가상 AI 분석에는 반드시 `데모 분석` 배지를 표시한다.

데모 분석은 영상 길이, 해상도, 음량 상태와 같은 제출물 품질 정보를 보여준다. 피치·음역·포즈·박자 분석은 `API 연동 예정`으로 표시하고 결과가 실제 측정값이라는 인상을 주지 않는다.

### 컨택 요청

엔터사는 `관심 저장`, `내부 검토로 이동`, `오디션 제안 보내기`를 선택할 수 있다. 제안에는 엔터사명, 검증 상태, 제목, 목적, 분야, 일정 또는 응답 기한, 담당 부서와 메시지를 포함한다.

지원자가 수락하기 전에는 개인 연락처를 공개하지 않는다. 데모에서는 수락 후 `컨택 승인` 상태와 후속 일정 카드가 나타나지만 실제 연락처 교환이나 외부 메시지 발송은 하지 않는다.

## 7. 후보자 파이프라인

파이프라인 단계는 다음으로 고정한다.

```text
신규 발견 → 관심 저장 → 내부 검토 → 제안 발송
→ 지원자 수락 → 미팅·추가 오디션 → 최종 검토 → 완료 또는 보류
```

각 카드에는 담당자, 최근 행동, 다음 작업, 팀 메모와 자료 상태를 표시한다. 카드는 드래그 또는 명시적 상태 변경 메뉴로 이동할 수 있다. 활동 기록에는 열람, 관심 저장, 제안, 수락, 담당자 변경과 단계 변경을 남긴다.

## 8. AX Command Center

### 운영 현황

- 신규 지원자
- 검토 대기 영상
- 응답을 기다리는 컨택
- 오늘 마감 업무
- 승인 대기 콘텐츠
- 예약 배포 콘텐츠
- 위험·지연 알림

### 오늘의 AX 브리핑

샘플 데이터를 기반으로 신규 지원자 수, 장기 미검토 후보자, 승인 대기 콘텐츠와 배포 일정의 요약을 제공한다. 브리핑에는 `Demo Agent` 표시를 적용한다.

### 자동화 카드

- 오디션 검수와 담당자 배정
- 결재·승인 요청
- 일정과 마감 알림
- 회의·업무 메모 요약
- 보도자료 초안
- A&R 데모곡 인박스 요약
- 지연 업무와 누락 경고

카드 상태는 `사용 가능`, `데모`, `API 연동 예정`, `사람 승인 필요`로 통일한다.

```text
원본 선택 → 홍보 목적 선택 → AI 작업 설정
→ 숏폼 후보 생성 → 캡션·해시태그 생성
→ 담당자 검수 → 채널별 예약 배포
```

- 길이: 15초, 30초, 60초
- 톤: 공식, 트렌디, 팬 친화적
- 자막 스타일
- 화면 비율

### 데모 결과

- 9:16 숏폼 미리보기
- 추천 구간 세 개
- 채널별 제목·캡션·해시태그
- 썸네일 후보
- 승인·수정·보류
- 예약 배포 일정

미리 제작한 샘플 결과물을 사용하며 실제 렌더링이나 게시를 수행하지 않는다.

## 10. Hermes 기반 AX 실행 구조

첫 공개 버전에서는 Hermes Agent를 실행하지 않지만 다음 경계를 UI와 타입에 반영한다.

```text
Enter-AX Web
├── 지원자·엔터사 인터페이스
└── 업무 관제·사람 승인
        ↓
Workflow Policy Layer
├── 역할·권한
├── 회사별 데이터 분리
├── 승인 규칙
├── 재시도·취소
└── 감사 로그
        ↓
Hermes Agent Runtime
├── 회사별 Bot과 메모리
├── 엔터 업무 스킬
├── 예약 작업
└── 도구·서브에이전트 실행
        ↓
MCP / API Connectors
├── 이메일·Slack·Teams·캘린더
├── Drive·문서·사내 시스템
├── 미디어 분석·렌더링
└── YouTube·Instagram·TikTok
```

### 에이전트 작업 상태

```text
대기 → 실행 중 → 사람 승인 대기 → 완료
                  ↘ 거절
실행 중 → 실패 → 재시도 또는 수동 처리
```

모든 에이전트 작업은 입력, 실행 단계, 사용 도구, 결과, 승인자, 오류와 재시도를 기록한다. 외부 메시지 발송, SNS 게시, 지원자 상태 변경은 기본적으로 사람 승인을 요구한다. 자동 합격·탈락은 허용하지 않는다.

Hermes의 자동 스킬 생성과 지속 메모리는 회사별 격리와 관리자 승인 정책 아래에서만 활성화한다. API 키와 비밀값은 Hermes 메모리나 작업 로그에 저장하지 않는다.

## 11. 기술 구조

### 유지할 기반

- Next.js 15 App Router
- React 19
- TypeScript
- Tailwind CSS 4
- Vercel

### 기능 모듈

- `talent`: 지원자 프로필·동의·미디어 등록
- `agency`: 엔터사 상태·인재 검색·컨택
- `pipeline`: 후보자 단계·담당자·메모·활동
- `ax`: 운영 브리핑·업무·에이전트 실행
- `content`: 홍보영상 자동화 워크플로
- `shared`: 레이아웃·내비게이션·상태·피드백 컴포넌트

### 데이터 접근

UI 컴포넌트는 데이터 원본을 직접 참조하지 않는다. 각 기능은 타입과 서비스 인터페이스를 노출하고 첫 버전은 Demo Adapter를 사용한다. 이후 동일한 인터페이스를 구현하는 API Adapter로 교체한다.

```text
UI → Feature Service Interface → Demo Adapter
                              ↘ Future API Adapter
```

데모 상태는 브라우저 저장소에 보존한다. 사용자는 `데모 초기화` 기능으로 원래 샘플 상태로 복원할 수 있다. 파일 객체와 객체 URL은 저장하지 않는다.

### 추가하지 않는 구조

- 별도 Python 서버
- 마이크로서비스
- 메시지 큐
- 실제 데이터베이스
- 실제 인증 제공자
- Hermes 또는 다른 에이전트 서버
- Remotion 렌더링 서버

## 12. 시각 디자인

디자인 방향은 `Editorial × AX Control Room`이다.

- 공개 랜딩과 지원자 화면: 밝은 아이보리 기반의 에디토리얼 구성
- 엔터사 대시보드: 딥 블랙·차콜 기반의 운영 콘솔
- 포인트: 일렉트릭 라임
- 보조 포인트: 코발트 블루
- 위험·지연: 오렌지 레드
- 한글 본문: Pretendard 계열
- 큰 제목: 폭이 좁고 강한 디스플레이 서체
- 얇은 구분선, 큰 수치, 명확한 상태 라벨
- 과도한 그라데이션, 글래스모피즘과 둥근 카드 사용 금지

동작은 상태 변화를 이해시키는 범위에서만 사용한다. 장식적 애니메이션보다 로딩, 작업 진행, 파이프라인 이동, 승인 결과에 집중한다.

## 13. 오류와 사용자 피드백

- 누락된 정면·좌·우 사진의 위치를 구체적으로 표시한다.
- 지원하지 않는 파일에는 허용 형식과 해결 방법을 제공한다.
- 잘못된 YouTube 주소는 제출 전에 입력란에서 표시한다.
- 공개 동의가 미완료되면 완료 버튼을 비활성화하고 이유를 설명한다.
- 미검증 엔터사는 인재 화면 접근을 차단한다.
- 중복 컨택은 새 요청을 만들지 않고 기존 요청 상태로 이동한다.
- 에이전트 작업 실패는 실패 단계와 재시도 또는 수동 처리 행동을 제공한다.
- 저장되지 않는 데모 작업은 성공한 실제 저장처럼 표현하지 않는다.

## 14. 접근성과 반응형

- 키보드만으로 핵심 흐름을 완료할 수 있어야 한다.
- 모든 입력에는 화면에 보이는 라벨이 있어야 한다.
- 색상만으로 상태를 전달하지 않는다.
- 본문과 인터랙션 요소는 WCAG AA 수준의 명암 대비를 목표로 한다.
- 의미 있는 이미지에 대체 텍스트를 제공한다.
- 영상에 재생 제어와 자막 상태를 제공한다.
- 지원자 등록과 제안 응답은 모바일 우선으로 구성한다.
- 엔터사 화면은 데스크톱 우선이며 태블릿까지 지원한다.
- 좁은 화면의 테이블은 카드 목록으로 전환한다.

## 15. 테스트와 수용 기준

### 지원자 흐름

- 정면·좌·우 사진 선택 시 각 미리보기가 표시된다.
- 보컬·댄스 입력은 파일과 YouTube 중 하나를 선택할 수 있다.
- 잘못된 YouTube 주소는 등록되지 않는다.
- 공개 범위와 필수 동의가 완료되어야 제출할 수 있다.
- 새로고침 후 선택한 로컬 파일이 남지 않는다.

### 엔터사 흐름

- 인재 검색 필터가 목록을 변경한다.
- 상세 프로필에서 모든 미디어 유형과 소스 상태를 확인할 수 있다.
- 관심 저장과 오디션 제안이 활동 기록에 반영된다.
- 지원자의 수락 후 후보자가 파이프라인에 나타난다.
- 파이프라인 단계 변경이 브라우저 저장소에 반영된다.

### AX 흐름

- 에이전트 작업을 만들고 상태를 진행시킬 수 있다.
- 사람 승인 대기 작업은 승인 또는 거절할 수 있다.
- 실패 작업은 재시도 또는 수동 처리로 전환할 수 있다.
- 홍보영상 작업의 입력부터 승인·예약 배포까지 완료할 수 있다.

### 품질 게이트

- TypeScript 검사가 통과한다.
- ESLint가 통과한다.
- 프로덕션 빌드가 통과한다.
- 핵심 흐름 자동 브라우저 테스트가 통과한다.
- 모바일·태블릿·데스크톱에서 가로 스크롤과 주요 겹침이 없다.
- 핵심 화면에 심각한 접근성 오류가 없다.
- 브라우저 콘솔에 처리되지 않은 오류가 없다.
- 깨진 내부 링크가 없다.

## 16. 배포와 전환

1. `enter-ax-design` 브랜치의 설계와 구현을 완료한다.
2. 로컬 테스트와 프로덕션 빌드를 통과한다.
3. GitHub 작업 브랜치를 Vercel Preview에 연결한다.
4. Preview에서 사용자 흐름과 반응형 화면을 검수한다.
5. 확인된 문제를 수정하고 품질 게이트를 다시 실행한다.
6. 사용자의 최종 확인 후 기존 Vercel Production으로 승격한다.

Preview 확인 전에는 기존 운영 배포를 덮어쓰지 않는다. 기존 Dazzling Studio는 Git 이력으로 복구할 수 있어야 한다. Vercel 보호 설정과 Production 도메인 전환은 최종 승격 시 확인한다.

## 17. 후속 단계

첫 데모가 승인된 뒤 실제 기능은 독립된 단계로 추가한다.

1. 인증·엔터사 검증·역할 기반 권한
2. PostgreSQL 기반 멀티테넌트 데이터
3. 보호된 미디어 업로드·스트리밍·보관기간 정책
4. Hermes Agent 샌드박스와 작업 큐
5. 이메일·메신저·캘린더 MCP 연결
6. 파일 업로드 영상의 보조 분석
7. 홍보영상 렌더링
8. 사람 승인 후 SNS 예약 게시
9. 운영 감사·비용·성능 모니터링

각 후속 단계는 별도 설계와 보안 검토를 거치며 첫 데모에 포함하지 않는다.
